# 自动交易评分与每日汇率修复设计

## 目标

修复无风控自动交易中“页面综合分达到最低分，但候选没有进入自动交易尝试池”的问题；将控制台 USD/CNY 固定汇率改为每日计算，获取失败时统一使用 7。

## 自动交易评分

严格风控模式维持现有排序：`finalRankScore`、综合分、24 小时成交量依次降序。

无风控模式改为按页面展示的综合分 `score` 降序，再按 `finalRankScore` 和 24 小时成交量降序。排序完成后仍只取配置规定的前 N 个候选。这样最低分判断、预算计算和候选优先级使用同一套用户可见分数。

最低分采用包含边界：综合分等于最低分时允许继续，只有小于最低分才跳过。

整轮没有成交时，不再只返回最后一个候选的原因。返回信息应包含实际被尝试候选的合约、综合分和跳过原因，使持仓上限、重复订单、重大新闻、计划生成或 OKX 拒单等原因可区分，避免用最后一个低分候选误导整轮结果。

## 每日 USD/CNY 汇率

汇率来源使用欧洲央行每日欧元参考汇率 XML。读取 EUR/USD 和 EUR/CNY 后计算：

`USD/CNY = EUR/CNY / EUR/USD`

应用启动后立即刷新一次，并在每天北京时间 00:00 刷新。刷新结果保存在进程内线程安全快照中，控制台接口只读取当前快照，不在每次请求时访问外部服务。

以下情况使用 `7`：

- HTTP 请求失败或超时；
- XML 无法解析；
- USD 或 CNY 字段缺失；
- 计算结果为零、负数或非法值。

兜底响应的来源标记为 `FALLBACK`；成功计算的来源标记为 `ECB`。更新时间为本次刷新完成时间。现有 `/api/quant/system/fx-rate` 响应结构保持不变。

## 错误处理与日志

外部汇率请求使用明确的连接和读取超时。失败日志仅记录异常类型和简短信息，不输出完整响应正文。失败不会影响应用启动和控制台主流程。

自动交易日志继续保留每个候选的阶段和原因，并在整轮结果中提供可定位的摘要。

## 测试

- 无风控模式下，综合分达标但排序分较低的候选必须优先于综合分不达标但排序分较高的候选。
- 综合分恰好等于最低分时通过评分门槛。
- 严格风控排序行为保持不变。
- 整轮失败摘要不能被最后一个低分候选覆盖。
- ECB XML 正常时验证交叉汇率计算。
- HTTP 失败、XML 非法、币种缺失和非法数值时验证汇率为 7、来源为 `FALLBACK`。
- 验证启动刷新和北京时间每日 00:00 调度配置。

## 范围外

自动交易真实净收益需要额外接入 OKX fills/bills，并补齐止盈、止损和平仓成交同步。这属于独立的数据链路改造，不与本次评分和汇率修复混合。
